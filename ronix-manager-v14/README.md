# RONIX V16

تحديث الربط الحسابي واستعادة صور المشاريع، مع الحفاظ على الواجهات وملاحظات V15 المنفذة. تحويله إلى تطبيق مستقل يبقى لمرحلة لاحقة.

**[تحميل النسخة الجاهزة V16](https://github.com/3amertarrab-oss/AA/raw/refs/heads/ronix-finance-download/ronix-manager-v14/RONIX-V16.zip)**

- ربط التحصيل تلقائيًا بالمطالبة عندما تكون هناك مطالبة نشطة واحدة متاحة لنفس المشروع والعميل. عند تعدد الخيارات يبقى المبلغ دون ربط حتى الاختيار اليدوي؛ لا نفترض ترتيبًا زمنيًا للسداد.
- تحديث الروابط التلقائية عند تصحيح مبلغ السند أو المطالبة أو إلغائها. المطابقات اليدوية محفوظة، وتُرفض التغييرات التي تتركها دون تغطية. زر «تفعيل الربط التلقائي» يعيد الحساب عند اختيار المستخدم.
- مصدر حسابي واحد لأرصدة المشروع والعميل ومركز التكلفة، مع أعمدة الربط في Excel. الربط لا يولد نقدًا جديدًا؛ تكلفة المشروع لا تجمع دفعة المصمم مع أتعابه مرتين.
- المستحق للمصممين والدفعات الزائدة يظهران منفصلين لكل تكليف، مع بيان صافي الرصيد دون تسوية تلقائية بين المشاريع.
- «استعادة صور المشاريع» يقرأ الصور فقط من ZIP الأصلي، ويطابق مساراتها المسجلة، ويضمّنها في أحدث الحسابات دون استبدال السجلات. لا يستبدل الصور الجديدة بصور الأرشيف.
- فحص البيانات يعرض الصور الخارجية والبيانات الناقصة والقبض غير المطابق والدفعات الزائدة. لا تُخمن أسماء المشاريع أو العملاء.

بيانات العملاء والصور والنسخة المستعادة الخاصة ليست ضمن الملفات العامة. التحديث العام خالٍ من بياناتهم.

## الملاحظات السابقة المحفوظة

| الملاحظة | الحالة وما تم |
|---|---|
| زر دفعة مستلمة | تم — يربط التحصيل بعميل المشروع ويحدد المشروع داخل نافذة السند. |
| أسماء المصممين وExcel | تم — أسماء المصممين في تقرير مراكز التكلفة وكشف مستقل لكل مصمم بصيغة XLSX فعلية. |
| عملة العقد وسعر الصرف وتاريخ المشروع | تم — القيمة الأصلية والمقابل بالجنيه محفوظان؛ القبض بعملته وفرق الصرف مستقلان. |
| التعاقدات الإضافية | تم — بنود باسم وتاريخ وقيمة تدخل في إجمالي التعاقد والمطالبات والتقارير. |
| تعديلات أتعاب المصمم | تم — الأصل + الأعمال الإضافية + الزيادات − الخصومات، مع التفاصيل في الكشف وExcel. |
| حذف دفعة المصمم | تم — استبعاد من الأرصدة مع سبب وسجل محذوفات واستعادة ومستند التحويل محفوظ. |
| صورة مركز التكلفة | تم — عرض صورة المشروع وتكبيرها وإضافة صورة من مركز التكلفة نفسه. |

المطالبة تحتفظ بالشعار الشفاف والمقدمة والألوان والإجمالي في النهاية، دون مراجع الدفعات. مستندات التحويل للمصممين والعملاء محفوظة مع النسخة الاحتياطية.

افتح `RONIX_Manager.html` بعد فك الضغط. إذا كانت صور JSON تشير إلى مجلد project_media، استخدم «استعادة صور المشاريع» واختر ZIP الأصلي بعد استيراد أحدث JSON، ثم صدّر نسخة جديدة. **صدّر أحدث JSON من النسخة التي تعمل عليها الآن، ثم استورده في V16**؛ لا تستعد ZIP قديمًا إذا أضفت حركات جديدة. البيانات الجديدة تستخدم الإصدار 16 من بنية الحفظ؛ افتح نسخها الاحتياطية بهذا الإصدار أو إصدار أحدث.

## العملات والحسابات

- الجنيه المصري أساس المجاميع والتقارير والمطالبات وأتعاب المصممين والمقدمات. العقود تدعم EGP وUSD وSAR وAED وEUR وGBP وQAR. المبالغ حتى منزلتين عشريتين وأسعار الصرف حتى ست منازل، وتُحفظ يدويًا مع العملية دون اتصال بأسعار حية.
- عقد المشروع = الأصل + التعاقدات الإضافية، بنفس عملة المشروع وسعر تعاقده. سعر التعاقد ثابت بعد وجود مطالبة أو تحصيل؛ سعر كل سند قبض مستقل.
- في سند القبض: «سداد من العقد» بعملة عقد المشروع؛ «مخصص من القبض» بعملة السند. عند تطابق العملتين يتساويان؛ وعند اختلافهما أدخل المبلغ الفعلي المخصص من السند، ويظهر فرق الصرف منفصلًا.
- مثال مختبر: عقد 1,200 USD بسعر 50 = 60,000 ج.م. قبض 400 USD بسعر 51 ثم 800 USD بسعر 52 يسدد العقد بالكامل؛ القبض 62,000 ج.م وفرق الصرف 2,000 ج.م ورصيد العقد صفر.
- المطالبات ومطابقتها تستخدم المقابل الدفتري بالجنيه. أتعاب المصممين والمصروفات والمقدمات تبقى بالجنيه؛ لا تعاد ترجمتها تلقائيًا بسبب عملة عقد العميل. لا توجد إعادة تقييم دورية لفروق صرف غير محققة أو دفتر أستاذ عام في هذه النسخة.
- الأتعاب النهائية = الأتعاب الأصلية + الأعمال الإضافية + الزيادات − الخصومات. دفعات المصمم لا تُضاف إلى التكلفة مرة ثانية.

## التحقق

اجتاز الإصدار 254 اختبارًا وتحققًا: 63 وحدة للحسابات والصور، و24 للربط واستعادة الصور بأحدث نسخة مستخدم، و29 لملاحظات V15، و42 لنقل النسخة الأصلية ووظائفها، و15 للحفظ والاستيراد، و25 للمستندات، و56 للعرض والطباعة. فُتحت ملفات XLSX الناتجة باستخدام openpyxl وفُحصت الأرقام وأسماء الأوراق والأنواع؛ لم يُشغّل Microsoft Excel في بيئة الاختبار. نسبة 100% تخص تنفيذ الملاحظات السبع، ولا تعني ضمانًا عامًا ضد جميع الأخطاء.

```bash
python build.py
node --test tests/core.test.js tests/r15-core.test.js tests/linking-core.test.js
python tests/review_v15.py
python tests/linking_browser.py --backup /path/to/latest.json --media-zip /path/to/original.zip
python tests/claim_print.py
python tests/attachments.py
python -m http.server 8004 --bind 127.0.0.1 --directory dist
```

ثم شغّل اختبارات `tests/reliability.py` و`tests/browser.py --zip /path/to/original.zip --original-dir /path/to/extracted/ronix_app`. يمكن تحديد `RONIX_TEST_URL` لاستخدام منفذ آخر. المتطلبات: Python Playwright وPyMuPDF وopenpyxl وChromium وNode. الصور والنسخ التجريبية الخاصة محفوظة في `private-test-artifacts` المتجاهل من Git.

البرنامج مستقل ويعمل دون تحميل مكتبات من الإنترنت. مصدر V13 المنقح محفوظ في `src/v13-base.html`، وقواعد الحساب الأساسية في `finance-core.js` والربط والأرصدة الموحدة في `accounting-links.js`، واستعادة الصور في `media-core.js` و`media-recovery.js`، وإضافات هذه المراجعة في `r15-projects.js` و`r15-payments.js` و`r15-integration.js`. التصدير الحقيقي إلى XLSX في `xlsx-export.js` باستخدام fflate المضمنة بترخيصها. هذا التنظيم يفصل الحسابات عن العرض ويساعد على نقلها لاحقًا إلى تطبيق.

الاختبار تم عبر HTTP محلي في Chromium؛ لا يشمل كل أنظمة Windows أو المتصفحات. التخزين لا يزال محليًا في المتصفح، بلا مزامنة أو نسخ خارج الجهاز تلقائيًا. احتفظ بنسخة JSON تشمل الصور والمرفقات بعد العمل.

راجع [المواصفات والمراجعة](المواصفات-والمراجعة.md) للتفاصيل وقواعد الحساب وحدود النسخة.
